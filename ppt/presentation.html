Clario RAG Architecture

Updated Deep Dive into UI, Data, Retrieval, Fallbacks, and Document Management

1. Pipeline Workflow

  • Ingestion: User uploads a document (PDF, DOCX, TXT, MD, CSV) or provides a URL. Text is extracted from the source.
  • Chunking: The text is split into smaller, overlapping chunks (e.g., 800 characters) to preserve context while meeting LLM token limits.
  • Embedding: Chunks are embedded with Gemini when available, with a local hashing-based fallback when Gemini has DNS or quota problems.
  • Storage & Retrieval: Saved in local ChromaDB. Queries combine vector retrieval with lexical matching for stronger fallback behavior.

2. How Data is Handled

  • File Processing: Uploads are temporarily saved via FastAPI, processed using libraries (pdfplumber, python-docx), and immediately deleted.
  • Text Processing: Raw text is cleaned, normalized, and systematically split into semantic chunks.
  • Document Management: The UI lists added documents and can delete all chunks for a selected document from ChromaDB.
  • State Management: The application keeps browser-side chat history and passes recent messages to the backend.

3. Core Algorithms Used

  • Recursive Character Text Splitting: Heuristic algorithm that splits text logically (paragraphs, sentences) to keep related text together.
  • HNSW (Hierarchical Navigable Small World): Used by ChromaDB for efficient Approximate Nearest Neighbor search.
  • Cosine Similarity: Mathematical metric used to calculate semantic distance between query vectors and document vectors.
  • Lexical Fallback Search: Keyword overlap protects short factual queries when Gemini is unavailable.
  • Structured Extractive Fallback: If Gemini returns 429, Clario formats relevant source passages into readable markdown instead of showing raw errors.

4. Data Science in this Project

Data Science is the core engine making this application intelligent:

  • NLP: Extracting structure and meaning from raw, unstructured data.
  • Representation Learning: Converting text into mathematical vector spaces (Embeddings).
  • Information Retrieval: Applying geometric distance algorithms in high-dimensional space to fetch relevant information.
  • Prompt Engineering: Constraining a generative language model with retrieved context to reduce hallucinations.
  • Resilience Engineering: Graceful fallbacks for Gemini rate limits, DNS failures, and greeting/small-talk inputs.

5. Where is User Data Stored?

  • Original Files: Nowhere persistently. Written to a temporary folder during extraction and immediately deleted.
  • Extracted Knowledge: Text chunks, their embeddings, and metadata are stored persistently in ChromaDB.
  • Storage Location: Database files are kept locally in backend/vector_store, including chroma.sqlite3.
  • Deletion: The Added Documents panel deletes all chunks matching the selected source filename or URL.
